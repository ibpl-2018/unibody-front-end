# Unibody — customer app (iOS + Android)

The Unibody storefront as a native app: browse Apple device parts by device/model/A-number, check fit and delivery, guest checkout with OTP, COD or online payment, and live order tracking. Built with **Expo SDK 57**, **expo-router** (file routes in `src/app`) and TypeScript (strict).

The API lives in the separate `unibody-back-end` repo; the web store is `../web`. This app talks to the API only.

## Quick start

```bash
npm install
cp .env.example .env.local        # then edit the URLs (see below)
npm start                         # Metro dev server; press i / a, or scan the QR code
npm run web                       # the same app in a browser at http://localhost:8081
```

The API must be running (`unibody-back-end`, default `http://localhost:4000`). In dev the API runs with `OTP_DEV_MODE` (the OTP code comes back in the response, and dev builds show a "tap to fill" hint) and `PAYMENTS_MOCK` (dev builds show a "Simulate payment (dev)" button on a pending online order).

### Environment

| Variable | Default | Purpose |
| --- | --- | --- |
| `EXPO_PUBLIC_API_URL` | `http://localhost:4000` | Unibody API base URL |
| `EXPO_PUBLIC_WEB_URL` | `http://localhost:3000` | Web store. Online payments open `${WEB_URL}/pay/<orderNo>?phone=…&return=unibody://order/<orderNo>` |

`EXPO_PUBLIC_*` values are inlined when the bundle is built, so restart Metro with `npx expo start -c` after you change them.

**Which host to use:**

- iOS Simulator: `http://localhost:4000` works.
- Android Emulator: `http://10.0.2.2:4000`, the emulator's alias for your computer.
- Physical phone (Expo Go or a dev build): use your computer's **LAN IP**, e.g. `EXPO_PUBLIC_API_URL=http://192.168.1.20:4000` and `EXPO_PUBLIC_WEB_URL=http://192.168.1.20:3000`. The phone and computer must be on the same Wi-Fi. The API has to listen on `0.0.0.0` and allow the origin in CORS (only the web build needs CORS). Product images come from the API as absolute `http://localhost:4000/static/...` URLs. On a phone, also set the API's `PUBLIC_URL` (backend `.env`) to the LAN IP, otherwise images will not load.
- Release builds must use **HTTPS** URLs. Android blocks cleartext HTTP and iOS ATS blocks it too, apart from local networking.

### Running on simulators and devices

```bash
npx expo start            # Expo Go works: every native module used ships with Expo Go
npx expo run:ios          # local dev build (needs Xcode), generates /ios via CNG
npx expo run:android      # local dev build (needs Android Studio), generates /android
```

`ios/` and `android/` are generated by Continuous Native Generation and git-ignored. Configure native behaviour in `app.json` and never edit those folders by hand.

### EAS builds

```bash
npx eas-cli@latest login
npx eas-cli@latest init                              # links the Expo project (adds extra.eas.projectId to app.json)
npx eas-cli@latest build --profile preview    --platform all   # internal: Android APK + iOS ad-hoc
npx eas-cli@latest build --profile production --platform all   # store builds (auto-incremented build numbers)
npx eas-cli@latest submit --profile production --platform ios|android
```

`eas.json` is committed. Both profiles point at `https://api.unibody.in` / `https://unibody.in`. Local iOS builds work on **Xcode 26.0+**: Expo SDK 57 officially needs Xcode 26.4, so `patches/expo-modules-jsi+57.1.1.patch` (applied by `postinstall`) makes its Swift build with Swift 6.2 — same behaviour, older compiler syntax. After upgrading `expo-modules-jsi`, drop the patch if the build passes without it. `npm run ios` / `npm run ios:release` target the iPhone 17 Pro Max. EAS builds don't need local Xcode.

- The bundle id and package are both `in.unibody.app`. The scheme is `unibody`.
- OTA updates are not set up yet (would need `npx expo install expo-updates` + `eas update:configure`).

## Features and route map

| Route (`src/app`) | Screen |
| --- | --- |
| `(tabs)/index` | **Home**: black hero with glow, search entry, shop by part, part finder (device, then model sheet, then "Show N parts"), device tiles, festive banner (from `store.config().banner`), bestsellers, Why Unibody, disclaimer |
| `(tabs)/shop` | **Shop**: device families (plus "your device") |
| `(tabs)/search` | **Search**: debounced search, A-number model matches, recent searches, suggestions |
| `(tabs)/bag` | **Bag** (tab badge = item count): qty stepper, remove, coupon, live `store.quote`, unavailable items, free-delivery and prepaid nudges |
| `(tabs)/orders` | **Orders**: OTP sign-in, then "My orders", plus orders tracked on this device and a Track entry |
| `shop/[family]` | Family: models with years, A-numbers and chips, plus popular parts |
| `parts` | Listing (`?family= / model= / category= / q= / sort=`): context card, category pills, filters sheet (condition, colour, price, in stock, COD), sort sheet, infinite scroll, "Fits your …" hints |
| `product/[slug]` | Product: gallery on a tinted stage, condition and explainer, finish/condition variants, price/MRP/% off, fit check (saved device or A-number via `store.checkFit`), pincode delivery check, qty, Add to Bag / Buy now, warranty chips, compatible models, related |
| `checkout` | Contact (name, phone, OTP send/verify with 6-digit input, lead saved after verify), address (pincode serviceability auto-fills city/state), GSTIN, payment (UPI/Card/Netbanking/COD with fee, limits and prepaid discount), summary, place order with `source` IOS/ANDROID |
| `confirmation/[orderNo]` | Confirmation. For online payments it shows a pending/retry state until the API reports `PAID` |
| `order/[orderNo]` | Tracking: status hero, vertical timeline, ETA, courier/AWB, items/totals/address, WhatsApp/call, cancel when allowed. Polls every 15 s while focused and supports pull-to-refresh. Asks for the phone number if it doesn't know it |
| `track` | Track by order number + phone |
| `more` | Help & settings: theme (Light/Dark/System), my device, help topics, WhatsApp/call, terms, disclaimer |

**Deep links:** `unibody://order/<orderNo>` opens the order. The payment page on the web store redirects there after a payment, which also closes the in-app browser.

**Online payment flow:** place the order, call `WebBrowser.openAuthSessionAsync(${WEB_URL}/pay/<no>…, unibody://order/<no>)`, then re-fetch `store.track` and read `paymentStatus`. The app never trusts the redirect alone.

## Project layout

```
src/
  app/                 routes (expo-router)
  components/
    ui/core.tsx        Text variants, Button, IconButton, Card, Input, Pill, Segmented, ListRow, Skeleton, EmptyState, ErrorState, Notice
    ui/commerce.tsx    Screen, FormScroll, BottomBar, Badge/ConditionBadge/StatusBadge, Price, ProductImage (tinted stage), QtyStepper, Sheet, Glow, Gradient, Logo

    order-parts.tsx    timeline, items/totals, payment-pending, help/cancel
    otp-input.tsx, summary.tsx, catalog-art.ts
  theme/               tokens (light/dark, tints, gradients) + ThemeProvider/useTheme (system default, override persisted)
  state/               cart (AsyncStorage, shared cart helpers, "my device"), session (OTP token, recent orders, searches), store config
  lib/                 config (env), api client, storage, payment, IST date formatting
  hooks/use-async.ts   tiny fetch hook (loading / error / refresh)
  shared/              VENDORED copy of ../shared/src. Do not edit here
```

Money is integer **paise** throughout. Format it with `formatINR` from shared.

## Shared code (vendored)

`src/shared` is a copy of `../shared/src` (itself synced from `unibody-back-end/shared`) (API client, DTO types, zod schemas, constants/labels, pricing, cart helpers). It is vendored rather than linked because Metro doesn't resolve files outside the project root without extra config, and because it keeps EAS builds self-contained.

To resync after shared code changes in unibody-back-end:

```bash
npm run sync-shared                     # copies ../shared/src (or run `pnpm sync-shared` at the repo root to pull from unibody-back-end first)
npm run sync-shared -- /path/to/unibody-front-end
npx tsc --noEmit
```

The script copies everything except `*.test.ts`. Keep `zod` pinned to the same version as `../shared/package.json` (currently `3.25.76`). If a fix is needed in shared code, make it in unibody-back-end first, then resync.
